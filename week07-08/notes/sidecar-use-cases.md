# Sidecar uses cases

Using a side car allows you to expand on a main app's funcionality without harming the soursecode. When observing the Pod you can determin that the pod only starts running if both the main app and sidecar are working, And given a working Pod the shared file system will continue to operate. You can also use ```kubectl exec sidecar-demo -c app -- kill ``` to restart only that container thus keeping the pod running. However, when the pod is deleted both containers stop and the shared data in the created volume emptyDir is deleted removed.

This is mostly used to add extra funtionality to a container without changing the main container. It seems like this is mainly used for logging, monitoring, data syncing, or acting as a proxy. This helps an aplication stay cleaner, more modular, and easier to maintain, while still gaining additional capabilities. In this one inparticular ```Hello from NGINX $(hostname)``` is saved to index.html from the main app and the sidecar prints the file content of index.html
